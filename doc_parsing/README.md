# 📄 文档解析管线

把中文上市公司年报 PDF 转成适合 RAG 检索的带元数据切块。**全程离线，不需要任何 API key。**

```
data/China/*.pdf  ──①──▶  data/markdown/*.md  ──②──▶  Document[]  ──▶  嵌入单元
     749 页                     114 万字符              1341 块          10610 个
                   pdf_to_markdown/          chunking/        chunking/indexing.py
```

| 阶段 | 目录 | 职责 | 详细文档 |
| --- | --- | --- | --- |
| ① 解析 | [`pdf_to_markdown/`](pdf_to_markdown/) | MinerU 把 PDF 转 Markdown | [README](pdf_to_markdown/README.md) |
| ② 切块 | [`chunking/`](chunking/) | 清洗噪声、还原层级、切块、附元数据 | [README](chunking/README.md) |

两个阶段以 `data/markdown/` 为交界。阶段 ① 耗时（749 页约 9 分钟）但只需跑一次；
阶段 ② 是纯内存计算，每次调用重新生成，方便反复调参。

## 🎯 为什么需要这一层

年报 PDF 拿通用 loader 直接读，会在几个地方悄悄崩掉，而且**都不报错**：

- 每页重复的页眉页脚混进正文，稀释语义
- 表格跨页后被拆成两张表，续表的首行数据被当成表头，真正的列名丢失
- `☑适用 □不适用` 里的勾选框是 Wingdings 私有区字符，不还原就无法判断选中了哪一项
- 一份年报里 `（2）按坏账计提方法分类披露` 出现 14 次，分属应收票据、应收账款、合同资产、
  其他应收款以及母公司报表，没有章节层级就完全无法区分
- 财务表格压成单个向量后，查"货币资金期末余额"要和其余 19 行抢同一个向量的表达能力

这个管线逐个处理了这些问题，并把每个修复固化成体检项，换数据源时能立刻发现失效。

## 🚀 快速开始

年报原文不在仓库里（`data/` 已 gitignore）。从[巨潮资讯网](http://www.cninfo.com.cn/)
下载 PDF 放进 `data/China/`，命名为 **`公司简称 + 四位年份 + 年报.pdf`**——
`company` 和 `year` 元数据由文件名解析，命名不符会导致跨年份过滤失效
（体检项「元数据解析失败」会报出来）。

```bash
pip install -U "mineru[core]" langchain-text-splitters

./doc_parsing/pdf_to_markdown/convert.sh            # ① 转换（幂等，跳过已处理的）
python doc_parsing/chunking/inspect_chunks.py       # ② 查看切块质量与体检
```

在代码里取用：

```python
from doc_parsing import load_all, build_embedding_units

parents = load_all()                       # 1341 块，交给 LLM 的文本
units = build_embedding_units(parents)     # 10610 个单元，拿去嵌入
```

## 📤 产出长什么样

每个块带公司、年份、章节路径、页码：

```python
{
    'company': '五粮液',
    'year': '2024',
    'source': '五粮液2024年报.md',
    'section': '第十节 财务报告 > 七、合并财务报表项目注释 > 1、货币资金',
    'page_start': 92,
    'page_end': 92,
    'chunk_id': '五粮液2024年报#166',

```

正文开头拼了一行上下文，让块脱离文档后依然自解释：


## 🔧 解决的几个问题

### 标题层级全部丢失

MinerU 把 **2317 个标题一律输出成 `##`**。年报遵循中文公文编号体例，据此可以还原深度：

| 编号形式 | 深度 | 数量 |
| --- | --- | --- |
| `第X节` | 2 | 39 |
| `一、二、` | 3 | 387 |
| `（一）（二）` | 4 | 59 |
| `1、2、` | 5 | 916 |
| `（1）` `1）` `①` | 6 | 885 |

还原后，同名章节的面包屑能区分开：

```
第八节 财务报告 > 七、合并财务报表项目注释     > 5、应收账款 > （2）按坏账计提方法分类披露
第八节 财务报告 > 十八、母公司财务报表主要项目注释 > 1、应收账款 > （2）按坏账计提方法分类披露
```

无编号标题（`致股东的信`）挂在最近一个编号标题之下——这样同级兄弟能拿到相同深度，
不会越嵌越深。

### 跨页表格被拆成两张

共 **162 处**。MinerU 把续表当成新表，首行数据被当作表头，还多插一条 `| --- |` 分隔行：

```markdown
<!-- 修复前：银行存款那行被当成表头，真正的列名"项目/期末余额/期初余额"丢失 -->
| 银行存款 | 78,907,591,498.82 | 74,892,248,621.63 |
| --- | --- | --- |
| 其他货币资金 | 202,456,023.63 | 264,472,639.86 |
```

### 勾选框变成乱码

`U+F052` 出现 **744 次**，是 Wingdings 字体透传出来的 ☑。年报里满是 `□适用 ☑不适用`，
不还原的话 LLM 根本判断不出选中的是哪一项。

> ⚠️ 这一项必须**在切分前**检查。`MarkdownHeaderTextSplitter` 会**静默吞掉**私有区字符——
> 未收录的勾选框不是变成乱码，而是直接消失，`☑适用 □不适用` 变成 `适用 不适用`，
> 选中项彻底丢失且不留痕迹。

### 表格嵌入被稀释

一张 20 行的表压成单个向量，查询"货币资金期末余额"要和其余 19 行抢表达能力。
所以**嵌入用的文本和给 LLM 的文本分开**：表格额外拆出行级单元单独嵌入，
命中后通过 `parent_id` 取回完整父块。

| 单元类型 | 数量 | 内容 |
| --- | --- | --- |
| `chunk` | 1341 | 整块，与父块一一对应 |
| `row` | 9269 | 表格单行，中位 112 字符 |

行级单元把列名一并写进去，脱离表格后依然自解释：

```
五粮液 2024年报 | ... > 1、货币资金 | 项目=银行存款 | 期末余额=78,907,591,498.82 | 期初余额=74,892,248,621.63
```

> 📌 约 **10% 的表首行其实是数据**——键值表（`股票简称|五粮液|股票代码|000858`）或表头缺失的续表。
> 强行当表头会产出 `张庆=男` 这种垃圾，所以靠"首行是否含纯数字单元格"判断，
> 没有表头就退化成纯值拼接。

## 🩺 体检

上面这些修复大多基于**硬编码假设**，换数据源时会失效，而且是**静默失效**——
不报错，只是悄悄产出更差的切块。所以每次运行 `inspect_chunks.py` 都会跑一遍体检：

```
🩺 体检
   ✅ 缺页码元数据
   ✅ 表格缺表头
   ✅ 元数据解析失败
   ✅ 私有区字符残留
   ✅ 超长块
   ✅ 标题层级扁平
```

| 体检项 | 什么情况会触发 |
| --- | --- |
| 元数据解析失败 | 文件名不是 `公司+四位年份+年报`。巨潮下载的 `贵州茅台2024年年度报告` 就不匹配 |
| 标题层级扁平 | 不遵循中文公文编号体例。英文报告的 `1.1 Overview`、港股年报都会退化成扁平 |
| 私有区字符残留 | 换用不同符号字体的 PDF，出现 `PUA_REPLACEMENTS` 未收录的字符 |
| 超长块 | 出现异常大的表格，有顶爆 embedding 上限的风险 |

## ⚠️ 选 embedding 模型时注意

实测（bge-m3 分词器）切块中位 **530 token**、最大 **3212**，**53% 超过 512**。

`bge-large-zh-v1.5`、`m3e-base`、`text2vec` 这类 512 上限的模型会**静默截断**六成以上的块，
不报错，只表现为检索质量莫名其妙地差。可选 BGE-M3（8192）、Qwen3-Embedding（32k）、
jina-embeddings-v3（8192）。

更多技术选型的取舍（为什么用结构切分而不是语义切分、为什么表格保留 HTML、
late chunking 为什么暂未启用）见 [`chunking/README.md`](chunking/README.md)。
